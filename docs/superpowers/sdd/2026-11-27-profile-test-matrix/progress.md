Ruling: `probeOnce(reason, runId, profileName)` gains an optional profile-name override used by `recordDiagnostic`; `runAllProfiles` passes the current test profile as the third argument (test stubs may ignore it). — why: the matrix must attribute rows to the profile actually applied — cost if wrong: all matrix columns for tested profiles would be empty and the winner would be chosen from mislabeled data.

Ruling: critical targets are always kept ahead of non-critical ones before the 10-target cap. — why: `overallOk` must never be silently based on a missing critical target — cost if wrong: health could be computed from a partial target set.
- Conflict: existing `http-probe.test.js` encodes the old "503 means OK" policy and existing `monitor-diagnostics.test.js` expects green with only one non-critical target. Ruling: update those two fixtures to the new 2xx/critical policy in Task 1 RED phase; they are contracts of the behavior this plan deliberately changes. — why: leaving them would make the suite contradict the spec — cost if wrong: strict policy would be reverted to satisfy stale tests.
- Task 1 ruling: `normalizeHealthTargets` drops the legacy `YouTubeShort` from inherited settings as well as defaults, not only from the default array. — why: it always answers 303 and would be a permanent false failure in every upgraded install — cost if wrong: one informational target stays red, but critical health is unaffected.
